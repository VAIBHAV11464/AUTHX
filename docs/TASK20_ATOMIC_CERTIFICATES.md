# Task 20 — atomic certificate issuance

Implemented 2026-09-28 after the reviewed Task 19 checkpoint. Scope ends here; Tasks 21–24 are not implemented. Legacy remains the default. No commit or push.

## Transaction and compatibility

`issue_certificate()` uses one SQLite connection and **`BEGIN IMMEDIATE`** before any certificate lookup. The same transaction covers existing-certificate lookup, authoritative session/result/lifecycle/eligibility reads, current override context, previous hash in certificate ID insertion order, immutable score serialization, collision checks, insertion and session certification. The certificate row is read before commit and returned after a successful commit. Helpers accepting the existing connection neither open another connection nor commit it. Any exception explicitly rolls back; connection close also releases an early-return read transaction.

An existing certificate returns first, including revoked certificates, old v2 evidence, expired/reopened/inconsistent historical session state, removed current results and changed configuration/labels. It is never reissued, rehashed or rebuilt. The authenticated route checks ownership, then delegates authoritative eligibility to the protected service; its old out-of-transaction prerequisite reads and duplicate-insert catch were removed. A new certificate still requires a complete scored attempt. V2 additionally requires the genuine stored server word and valid gated machine snapshot inside the transaction. Direct service callers retain `None` for ordinary ineligible attempts; the API asks for the existing specific word/evidence failure reasons. Expired unfinished attempts still return the lifecycle error.

ID collision retries use the same locked connection, with the prior five-candidate limit. Concurrent submissions for one session return one identical certificate. Different sessions serialize into a single append order. Reopen and faculty override writes share SQLite's writer serialization: a reopen after issuance rotates the certified attempt; a reopen before issuance leaves the old attempt incomplete and unable to issue. A label action after issuance cannot alter the frozen snapshot; an action before issuance is captured with its separate machine/audit meaning.

The existing hash algorithm is unchanged: SHA-256 of UTF-8 `f"{prev_hash}{session_id}{trust_score}{created_at}{score_json}"`, with `GENESIS` and original JSON sorting/separators. New legacy payloads are byte-equivalent to the previous serializer. New v2 snapshots include Task 19's active override context read under the same lock. No old certificate serialization, timestamp, trust text, hash, previous link, row order or revocation behavior is rewritten. A previously broken chain remains visibly broken; this implementation does not repair it.

Final review also ensures trust-save return values are captured before commit, authorized faculty detail/audit reads share a read snapshot, and certified sessions cannot start measurement even if historical results are absent. These close lifecycle boundary cases without changing scores, weights, capture or the flow.

Focused lifecycle coverage now includes certified sessions with missing historical results. This is the verification needed for Tasks 19–20, not the broader Task 21 expansion or later evaluation harness.

The before/Task19/after archives and hash manifests, SQLite backup, exact logs and algorithm/serializer audit are local in `backups/task19-20/`. All tests initialize only temporary databases. The preserved real database, accounts, enrollments, history and issued certificate rows remain unchanged; migrations run only on isolated fixtures/read-only-derived copies during QA. Next ordinary app startup applies the additive schema migration.

Limits: SQLite's existing connection busy timeout can report lock contention if an external writer holds a lock too long; issuance keeps its transaction short and runs no media inference under the lock. Tests use concurrent independent connections on isolated databases, not a production multi-host deployment. No live volunteer/hardware/accuracy/spoof/accent/latency study. V2 remains opt-in; stop before Task 21.
