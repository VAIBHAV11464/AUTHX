# Task 19 — session lifetime, certified rotation and faculty audit

Implemented 2026-09-28 in the authorized Tasks 19–20 batch. Legacy remains the default. No commit, push, dependency change or model installation.

## Lifecycle semantics

An unfinished attempt is an `open` session, including a saved Look or saved Speak that has not yet saved trust. It expires **at age >=600 seconds**, using the original timezone-aware UTC `started_at`. Malformed/non-UTC unfinished start times fail closed. Expiry is derived on access; there is no background cleanup, deletion or rewrite of historical rows. It survives restart because the deadline comes from SQLite, not browser state. Scored and certified history does not age out. A new trust save records completion time; historical completion timestamps are not backfilled.

Authenticated ownership checks precede lifecycle/evidence responses. Look, Speak, trust and new certificate requests check the deadline before measurement/prerequisites. Scoring saves recheck within `BEGIN IMMEDIATE`. The existing 120-second Speak lease remains distinct from the ten-minute lifetime. A submitted Speak crossing expiry releases only its own reservation, keeps the spent submission, saves no voice/evidence, and returns 409 `session_expired`, `retryable:false`, `freshSessionRequired:true`. Superseded workers cannot save or refund another worker's reservation. The existing failure-detail string handling remains.

Uncertified reopen retains the same ID, profile, challenge, start time, Speak count and last failure evidence. It cannot extend the deadline: reopen is denied once the original deadline passes, even for a scored attempt being changed back to open. Existing v2 lease/exhaustion restrictions remain. Successful reopen increments additive `attempt_generation`; late Look, legacy Speak and trust workers also check their starting generation/result ID inside the save transaction. Prior override records remain history and no longer apply to the new generation.

A certificate's existence is authoritative for rotation, including revoked certificates and historical inconsistent session status. Certified reopen creates a new UUID session with fresh server-selected challenge/timing, start time, zero retries and the **original pinned profile**. Random selection can repeat a word/time. The old session, result, completion time, certificate bytes and hashes are preserved. An additive `session_rotations` table makes repeated/concurrent reopen of the same certified ID return one successor rather than create duplicates. Faculty responses add `sessionId`, `previousSessionId`, `newSession`, word/timing/profile where applicable. The existing faculty view navigates to the successor; ordinary reopen clears its current metrics.

## Separate machine and faculty records

Additive nullable `sessions.machine_trust_score`/`machine_risk_label` preserve new machine outcomes for both profiles. V2 keeps its detailed Task 17 machine snapshot; legacy also saves the original fusion output in detail JSON. Repeated completed trust calls read saved outcomes/configuration rather than rescore under today's settings. Concurrent trust saves retain the first completed machine decision. A selected faculty label remains the effective label when trust finishes, without changing machine eligibility or measurements.

`faculty_overrides` records each authenticated faculty/admin action transactionally with the effective label write: server actor ID/role, UTC time, selected and previous label, attempt generation, and available machine score/label. Client actor/time fields are ignored. No actor/history is invented for old labels. Existing label selection and roles remain; auditing labels on an expired/certified attempt does not unlock scoring or change certificates. Authorized faculty detail includes the audit history; current evidence shows the active generation's override separately from the machine outcome. New v2 certificate snapshots freeze this distinction. Legacy certificate serialization retains its original exact fields; its outcome label is frozen, with audit context available only in authorized current session views.
